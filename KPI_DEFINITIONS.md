# AI Office — KPI Definitions & Source Map

Every management-facing KPI in AI Office, what it precisely means, where its number comes from, and whether it can honestly support a previous-period comparison. Written from a direct code audit (not from memory) — see each row's file reference to verify. This is the canonical definition; screen-level subtitle text should always match what's written here, and any drift found later should be fixed here first, then propagated, not the other way round.

Governing rule: see `DATA_INTEGRITY.md`. Nothing here is ever "adjusted" to make two KPIs reconcile — where two KPIs represent genuinely different concepts (e.g. "Enquiries" vs "GA4 Enquiries"), that distinction is preserved deliberately, not smoothed over.

| KPI | Definition | Source | Status | Distinct from |
|---|---|---|---|---|
| **Website Users** | GA4 `activeUsers` for the selected entity/period — never `sessions`. | `src/utils/ga4Traffic.ts` `getWebsiteUsers()`/`getWebsiteUsersForBrand()` | Real, per brand with a configured GA4 property | **Sessions** (same GA4 response, different field, shown separately on Reports/Social/Email) |
| **Sessions** (incl. Social Sessions) | GA4 `sessions` metric. "Social Sessions" is a *separate* GA4 query filtered to Organic/Paid Social channel groups — not derived from Website Users. | `ga4Traffic.ts` (`getWebsiteUsers`, `getSocialTraffic`) | Real, where GA4 configured | Website Users (`activeUsers`) |
| **GA4 Enquiries** | A confirmed-live GA4 key event representing a real website conversion action (form/phone/email/live-chat), per brand, from a hand-verified event list per brand. **Never** GA4's generic "conversions" total. | `backend/src/services/ga4.ts` `ENQUIRY_EVENTS_BY_BRAND` + `getEnquiries()`; frontend `src/utils/ga4Enquiries.ts` | Real, verified live for **brentwood, ircl, radio-links, capcom only**. `mtech`/`idaro` have no confirmed definition and are permanently excluded (not "not connected" — structurally out of scope until a live diagnostic is run for them) | Plain **Enquiries** — never summed together anywhere in the codebase |
| **Enquiries** (plain) | Sum of each campaign's manually-entered `results.enquiriesReceived` field, for campaigns in the filtered entity+period set. A human-logged, campaign-level count. | `src/utils/campaignMetrics.ts` `sumEnquiries()`; entered via `LogResultsModal.tsx` | Real, but manual — never automatically synced | GA4 Enquiries — different concept, different source, never summed together |
| **Marketing Leads** | Sum of each campaign's manually-entered `leads` field. | `campaignMetrics.ts` `sumLeads()`; entered via `EditCampaignModal.tsx` | Real, manual, **not CRM-verified** | Qualified Leads (permanent stub, below) |
| **Qualified Leads** | Not computed anywhere. Permanent "Not connected" placeholder pending Acumatica. | None — hardcoded on `LeadsCrmScreen.tsx` | Stub | Marketing Leads |
| **Opportunities** | Every genuinely imported Acumatica Opportunity ID within the filtered date range/entity, regardless of Status. Manual import only — never live. | `backend/src/services/acumaticaReporting.ts` `getAcumaticaSummary()`; classification rules centralised in `acumaticaKpiRules.ts` | Real, on **Leads & CRM only** — every other screen (Campaign Detail, Performance, Reports, Home, PPC, Call Tracking) still shows the old "Not connected" stub, not yet wired to this data | Qualified Leads (still a stub — no lead-level data in the export) |
| **Won Deals** | Count of imported opportunities with Status exactly `"Won"` (confirmed real value, exact/case-insensitive match only — never inferred from Stage). | `acumaticaKpiRules.ts` `isWonStatus()` via `getAcumaticaSummary()` | Real, on Leads & CRM only | — |
| **Won Revenue** | Sum of `total` across Won opportunities (as above). | `acumaticaKpiRules.ts` + `getAcumaticaSummary()` | Real, on Leads & CRM only | Campaign Detail's `valueGenerated` (still unconnected, a different, separately manually-entered figure feeding ROI only) |
| **Pipeline / Open Pipeline** | **Provisional.** Sum of `total` for opportunities with Status exactly `"Open"` only. The real export also contains a `"New"` status (68 of the first 1,000 rows sampled) not yet confirmed as pipeline-or-not with the sales/Acumatica team — see `acumaticaKpiRules.ts`'s `OPEN_PIPELINE_STATUSES`/`PIPELINE_DEFINITION_CONFIRMED`. The KPI card is labelled "Open Pipeline (provisional)" and always shows the excluded New count/value alongside it. Every other screen still shows the old "Not connected" stub. | `acumaticaKpiRules.ts` + `getAcumaticaSummary()` | Provisional/real on Leads & CRM only — do not treat as final until confirmed | — |
| **Marketing Spend** | Sum of each campaign's manually-entered `spend` field. | `campaignMetrics.ts` `sumSpend()`; entered via `EditCampaignModal.tsx` | Real, manual, not linked to any spend-tracking API | **Google Ads Spend** — a genuinely different, API-sourced figure, shown only on the PPC screen, never summed with this one |
| **Google Ads Spend** | Real Google Ads campaign cost (`costMicros / 1,000,000`), summed from the live Google Ads API for the period. | `backend/src/services/googleAds.ts`; frontend `src/utils/googleAdsPerformance.ts` | Real, API-connected — **Brentwood and Radio Links only** (Capcom/IRCL have no Google Ads account configured) | Marketing Spend (manual, campaign-level) |
| **ROI** | `((valueGenerated − spend) / spend) × 100`, Campaign Detail only. | `src/screens/CampaignDetailScreen.tsx` (computed inline, not extracted to a shared util) | Arithmetically real, but both inputs are manually entered with **no real commercial data behind either** — `valueGenerated` in particular carries no "not verified" caveat in its own subtitle today, unlike Marketing Leads/Spend | — |

## Naming drift found during this audit (documented, not yet unified everywhere)

- The "Marketing Leads ... not CRM-linked" caveat exists as **three different literal strings** across six files: `"Manually logged, not yet CRM-linked"`, `"Manually logged, not CRM-linked"`, and `"Manually logged - not CRM linked"`. `src/utils/campaignMetrics.ts` now exports a single `MARKETING_LEADS_CAVEAT` / `MARKETING_SPEND_CAVEAT` constant (see that file) — screens should be migrated to it over time; not all call sites were changed in this pass to keep the diff controlled, per the "do not redesign working screens" instruction for this phase.
- "Pipeline" vs. "Open Pipeline" vs. "Pipeline Value" are used inconsistently for the same stub concept across 8+ screens. Not unified in this pass (label-only change to already-correct "Not connected" stubs; low risk but broad diff — flagged for a deliberate follow-up rather than done opportunistically here).

## Which KPIs can honestly support a previous-period comparison

See `REPORTING_PERIOD.md` for the full per-source reasoning. Short answer: **Website Users, GA4 Enquiries, Enquiries, Marketing Leads, Marketing Spend, and Google Ads Spend/Clicks/Conversions** — all real, bounded, traceable figures. Everything else (Qualified Leads, Opportunities, Pipeline, Won Revenue, ROI, Funding) is excluded, each for the specific reason listed in `REPORTING_PERIOD.md`.
