# AI Office — KPI Definitions & Source Map

Every management-facing KPI in AI Office, what it precisely means, where its number comes from, and whether it can honestly support a previous-period comparison. Written from a direct code audit (not from memory) — see each row's file reference to verify. This document describes the implementation. Current code is authoritative; investigate discrepancies before proposing any KPI definition change.

Governing rule: see `DATA_INTEGRITY.md`. Nothing here is ever "adjusted" to make two KPIs reconcile — where two KPIs represent genuinely different concepts (e.g. "Enquiries" vs "GA4 Enquiries"), that distinction is preserved deliberately, not smoothed over.

| KPI | Definition | Source | Status | Distinct from |
|---|---|---|---|---|
| **Website Users** | GA4 `activeUsers` for the selected entity/period — never `sessions`. | `src/utils/ga4Traffic.ts` `getWebsiteUsers()`/`getWebsiteUsersForBrand()` | Real, per brand with a configured GA4 property | **Sessions** (same GA4 response, different field, shown separately on Reports/Social/Email) |
| **Sessions** (incl. Social Sessions) | GA4 `sessions` metric. "Social Sessions" is a *separate* GA4 query filtered to Organic/Paid Social channel groups — not derived from Website Users. | `ga4Traffic.ts` (`getWebsiteUsers`, `getSocialTraffic`) | Real, where GA4 configured | Website Users (`activeUsers`) |
| **GA4 Enquiries** | A confirmed-live GA4 key event representing a real website conversion action (form/phone/email/live-chat), per brand, from a hand-verified event list per brand. **Never** GA4's generic "conversions" total. | `backend/src/services/ga4.ts` `ENQUIRY_EVENTS_BY_BRAND` + `getEnquiries()`; frontend `src/utils/ga4Enquiries.ts` | Real, verified live for **brentwood, ircl, radio-links, capcom only**. `mtech`/`idaro` have no confirmed definition and are permanently excluded (not "not connected" — structurally out of scope until a live diagnostic is run for them) | Plain **Enquiries** — never summed together anywhere in the codebase |
| **Enquiries** (plain) | Sum of each campaign's manually-entered `results.enquiriesReceived` field, for campaigns in the filtered entity+period set. A human-logged, campaign-level count. | `src/utils/campaignMetrics.ts` `sumEnquiries()`; entered via `LogResultsModal.tsx` | Real, but manual — never automatically synced | GA4 Enquiries — different concept, different source, never summed together |
| **Marketing Leads** | Sum of each campaign's manually-entered `leads` field. | `campaignMetrics.ts` `sumLeads()`; entered via `EditCampaignModal.tsx` | Real, manual, **not CRM-verified** | Qualified Leads (permanent stub, below) |
| **Qualified Leads** | Not computed anywhere. Permanent "Not connected" placeholder pending Acumatica. | None — hardcoded on `LeadsCrmScreen.tsx` | Stub | Marketing Leads |
| **Opportunities** | Imported Acumatica opportunities, regardless of Status, within the requested entity and Created On range. | `backend/src/services/acumaticaReporting.ts` `getAcumaticaSummary()` | Overview uses the full latest import; Performance and Leads & CRM use the selected Created On range. Other views may retain placeholders. | Qualified Leads (no lead-level dataset) |
| **Won Deals** | Count of imported opportunities with Status exactly `"Won"` (confirmed real value, exact/case-insensitive match only — never inferred from Stage). | `acumaticaKpiRules.ts` `isWonStatus()` via `getAcumaticaSummary()` | Real, on Leads & CRM only | — |
| **Won Revenue** | Sum of `total` for current imported Status Won. Overview uses the full latest import; Performance and Leads & CRM filter opportunity Created On for a selected period. This is not revenue that became Won during that period. | `acumaticaKpiRules.ts` + `getAcumaticaSummary()` | Manual import; no trustworthy Won Date is persisted | Manually entered `valueGenerated` |
| **Pipeline / Open Pipeline** | Sum of `total` for Status Open **plus New**. Stage never determines commercial status. | `acumaticaKpiRules.ts` + `getAcumaticaSummary()` | Confirmed classification; same screen/date scopes as Opportunities | Stage breakdown and Sales-reported Source are separate dimensions, not attribution |
| **Marketing Spend (legacy)** | Sum of manually stored `campaign.spend`. Retained in Reports and MTech HQ; not the canonical Known Campaign Spend calculation. | `campaignMetrics.ts` `sumSpend()` | Legacy, not migrated in Phase 1 | Known Campaign Spend and Google Ads Spend |
| **Google Ads Spend** | Google Ads cost (`costMicros / 1,000,000`) for the requested period. Overview retains this as its headline spend KPI. | `backend/src/services/googleAds.ts`; `src/utils/googleAdsPerformance.ts` | Availability depends on configured accounts and response coverage | Known Campaign Spend includes fixed costs and only available, explicitly mapped campaign media |
| **ROI (legacy Campaigns table)** | `((valueGenerated - campaign.spend) / campaign.spend) * 100`, when inputs permit. | `src/components/campaigns/CampaignsTable.tsx` | Manual inputs; still uses legacy spend although the adjacent spend column is canonical. Deliberately unchanged in Phase 1. | Acumatica Won Revenue and canonical spend |
| **Fixed Costs** | Structured campaign cost rows take precedence, including a genuine zero sum. If none exist, positive legacy campaign spend is a labelled fallback; otherwise the helper returns zero for the supplied empty dataset. | `src/utils/campaignCosts.ts` | Callers must distinguish unavailable rows from successfully empty rows | Media spend |
| **Known Campaign Spend** | Fixed Costs plus available Google Ads spend using the existing explicit campaign mapping. Unavailable or unmapped media is excluded from the known total and remains labelled, not presented as measured zero media spend. | `src/utils/campaignCosts.ts` | Overview campaign rows, Campaigns and Campaign Detail use lifetime fixed costs plus all-time-query media. Performance uses lifetime fixed costs plus selected-period media. | Spend incurred within the reporting period |

## Deliberate remaining differences

- Reports and MTech HQ retain legacy campaign membership/spend behaviour. They were outside the required Home, Performance and Leads & CRM migration.
- Marketing Leads caveat wording and unconnected commercial placeholders are not unified across every screen.
- The Campaigns table ROI denominator remains legacy spend. No ROI definition was changed.
- Acumatica excludes IRCL and Source Lead. Sales-reported Source is not deterministic attribution. Entity resolution uses explicit entity information and the confirmed ID-prefix fallback, not Stage.

## Previous-period comparisons

See `REPORTING_PERIOD.md` for source-specific limits. Existing comparisons cover Website Users, GA4 Enquiries, manually logged campaign Enquiries/Marketing Leads and Google Ads metrics. Campaign counts describe selected campaign cohorts, not dated individual lead/enquiry events. Known Campaign Spend has no comparison because its fixed-cost and media scopes differ. Acumatica commercial KPIs, ROI and Funding remain excluded.
